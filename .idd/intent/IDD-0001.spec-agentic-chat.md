# IDD-0001.spec-agentic-chat

## Intent

Provide an interactive chat surface for running a selected agent or saved workflow.

## Related Specifications

Related: IDD-0002, IDD-0004, IDD-0005, IDD-0007, IDD-0009, IDD-0010.

## Behavior

Users select an available agent or workflow, supply required inputs, and exchange messages. Responses stream into the transcript; users can cancel an active response and copy the conversation as text, Markdown, or HTML. The transcript exposes assistant reasoning and tool activity when supplied by the runtime. Internal runtime feedback used solely to continue an autonomous run is not shown in the user transcript. A direct-agent conversation with available runtime session state exposes a compact, initially collapsed Session state panel beside the conversation copy action. The panel shows the current runtime mode and/or TODO list when those capabilities are available, including an empty TODO list; it refreshes after session creation, each successful runtime tool action that changes the session mode or TODO list, completed runs, runtime mode changes, and conversation reset. When the direct session has an Agent Mode Provider, its effective runtime modes are offered as a compact selector. The user may select a mode before the first message or between runs; the selection changes only the current session's runtime mode, does not add a transcript message or run the agent, and applies to the next invocation. The selector is unavailable during an active run and absent when no Agent Mode Provider exists; a single effective mode is displayed read-only. Workflow conversations do not present an ambiguous combined session state.

## Durable Architecture And Constraints

Conversation execution supports both direct agents and workflow-based agents.

Session-state display is a projection and control surface for the active direct conversation's runtime session. Agent-session state remains the sole owner of modes and TODOs; saved-agent configuration, transcript/tool history, and UI state do not substitute for it. Intermediate refreshes observe the active session and must not restore state from a cancelled or reset conversation. A saved Agent Mode Provider profile's default initializes each new session only; changing a session mode never changes the saved profile or a different session. The selector uses the effective modes materialized for that runtime agent, so edits to a saved profile do not alter an existing conversation's options. Switching modes preserves the same agent session and its TODO state.

## Non-Goals

This surface does not define how agents, workflows, servers, or tools are authored.

## Acceptance Criteria

- A valid selection can receive a user message and return streamed output.
- Cancellation leaves the conversation in a usable state.
- Users can export the displayed transcript in each offered format.
- A direct conversation with a mode or TODO capability can reveal its current session state without opening a separate TODO page.
- A direct conversation with an Agent Mode Provider offers its effective runtime modes and confirms the runtime value after a successful change; mode selection is available before the first message and between runs without creating a message, invocation, or new session.
- Mode selection preserves the current session's TODOs and does not modify the saved provider profile; a new chat again initializes its mode from the profile default.
- A direct conversation with a TODO capability distinguishes an empty list from an unavailable capability, and a new conversation does not display TODOs from the previous session.
- During an autonomous direct-agent run, the Session state panel visibly reflects successful TODO and mode changes before the whole run completes, while runtime continuation feedback is absent from the transcript.
- A workflow conversation does not select or aggregate a participant's session state.

## Verification

Automated coverage verifies streaming, cancellation, transcript state, export formatting, runtime session-state projection, autonomous-run state-change projection, and direct-session mode switching without an invocation or session replacement. Manual verification confirms session-state updates across runs and resets, including changing a mode before the first message and between turns.
