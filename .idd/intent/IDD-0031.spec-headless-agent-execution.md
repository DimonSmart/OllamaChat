# IDD-0031.spec-headless-agent-execution

## Intent

OllamaChat supports manually executing a Saved Agent associated with a Scheduled Task without opening or altering an interactive chat. The execution is owned by the application host and is reusable for future schedule-triggered invocation.

## Behavior

- A Scheduled Task may optionally reference a Saved Agent and store a prompt. The binding refers to the live Saved Agent definition, never a copied agent configuration.
- A user may manually launch the bound agent whether the timer is enabled or disabled. Invalid or deleted agent definitions are diagnosed at launch, without corrupting or disabling the Quartz timer.
- The manual run is a distinct operation with its own identity, status and final answer or safe error. One manual execution may be active across the application at a time; additional requests are rejected, not queued.
- The user can request cancellation and see that cancellation or a timeout is pending while work is still running or being cleaned up. Completed, failed, canceled and timed-out states are not published until all execution work and resources have stopped.
- Closing the dialog, navigating away or losing the initiating Blazor circuit does not cancel the execution. Results and status may be retrieved again while the same host process is running.
- Only final assistant text is shown, with a visible truncation indicator for long output. Tool transcripts, live deltas and interactive prompts do not appear in the manual-run dialog.

## Architecture And Constraints

- Every accepted run executes the existing agent runtime/runner in a separate DI scope with its own root run context, null conversation ID and exactly one initial user message. There is no prior chat history or session continuation.
- Runtime uses the Saved Agent and its current configuration at launch. Changes after the launch snapshot apply to subsequent runs only.
- The coordinator holds an application-wide single-flight slot through preflight, execution, cancellation and resource disposal. It observes host shutdown, distinguishes cancellation from timeout, and uses bounded in-process state.
- Manual run results and status are never persisted in the Scheduled Tasks JSON, Saved Chats, chat histories, Harness File Memory or another execution database. Restart clears them.
- Headless runs cannot inherit approval grants or route requests into an interactive Blazor/MCP session. Approval must fail closed, and capabilities that cannot be safely isolated are explicitly rejected before starting rather than silently stripped.
- The app continues to use Quartz only for diagnostic timer firing notifications. Quartz does not trigger agents in this iteration.
- Deleting a timer makes it unavailable for future manual runs, cancels its active execution and removes its stored terminal result. Manual runs do not mutate the timer schedule, enabled state or Quartz triggers.

## Non-Goals

- Automatic execution on Quartz firing, headless workflows, persistent execution history, streamed transcripts, interactive approvals, automatic workspace creation, multiple concurrent runs or continued execution after process shutdown.

## Acceptance

- A text-only Saved Agent with an explicitly configured model can be manually run from Scheduled Tasks, returning the terminal result of the existing runner without creating a chat.
- Concurrent attempts, cancellation, timeout, deleted/missing agents and broken timer storage have understandable outcomes without affecting Quartz or other circuits.
- A run is isolated from other chat sessions, including prior approvals, tools and history. Unsupported capabilities fail before execution.
- Agent binding edits leave the schedule and interval anchors unchanged; disabled timers can still launch manually.
- Terminal results are bounded and available during the host lifetime, but disappear after restart or timer deletion.
