# IDD-0022.spec-agent-mode-provider-profiles

## Intent

Let users manage reusable Agent Mode Provider profiles that define agent operating modes and their behavioral instructions.

## Related Specifications

Related: IDD-0001, IDD-0005, IDD-0020, IDD-0021.

## Behavior

Users can create, search, edit, and delete named Agent Mode Provider profiles. Each profile contains one or more uniquely named modes with non-empty instructions and names a default mode from that set. A profile can optionally provide common provider instructions; empty common instructions defer to Microsoft Agent Framework defaults. Custom common instructions must contain `{available_modes}` and `{current_mode}`. A saved agent may optionally select one profile; that selection makes its configured modes available for the agent's sessions. A session's current mode starts from the selected profile's default and can subsequently be changed through the direct-chat session-state control without changing the profile.

## Durable Architecture And Constraints

Agent Mode Provider profiles and modes are application-owned persisted models. They do not expose or persist Microsoft Agent Framework runtime types. The saved-agent runtime materializes a selected profile into its provider configuration without persisting runtime types, and retains the resulting effective mode list for the lifetime of that conversation. A profile containing the exact mode name `execute` can satisfy the saved agent's optional TODO-completion configuration; the profile itself does not enable continuation.

## Non-Goals

This capability does not enable automatic continuation by itself or provide manual profile editing from chat.

## Acceptance Criteria

- Profile names are required and unique without regard to case.
- A profile has at least one mode; every mode has a distinct name and non-empty instructions.
- The default mode is required and exactly matches a configured mode name.
- Custom provider instructions preserve multiline content and include both required placeholders; absent instructions use future framework defaults.
- Deleting a profile requires confirmation, and the profiles catalog is available from main navigation near reusable agent configuration.

## Verification

Automated coverage verifies profile CRUD persistence, timestamps, validation, placeholder rules, and round-trip preservation of multiline mode instructions. Manual verification confirms search and create/edit/delete interactions, including adding and removing modes.
