# IDD-0027.spec-agent-skills-provider-profiles

## Intent

Let users configure reusable Skills Provider profiles for saved Harness agents, using workspace Claude-compatible skills and selected Markdown skill files.

## Related Specifications

Related: IDD-0001, IDD-0005, IDD-0020, IDD-0023, IDD-0024.

## Behavior

Users can create, edit, reorder, and delete named Skills Provider profiles. A profile can include Claude-compatible skills from `.claude/skills` in the conversation workspace and ordered file sources. Each file source declares a directory and one or more relative glob patterns. Relative directories resolve from the session workspace; absolute directories identify installed external skill locations. New file sources suggest `**/skill.md` and `**/skill_*.md` without restricting other relative patterns.

A saved agent may select one Skills Provider profile. No selection disables skills. A missing selected profile is visible as unavailable and does not silently become no selection. Skills are discovered once while the direct Harness session is created and remain unchanged for that session. The session workspace is chosen before the conversation starts and cannot be changed after the conversation has started; starting a new conversation is required to use another workspace.

Each glob-matched Markdown file is one skill and must contain non-empty YAML frontmatter `name` and `description`, followed by non-empty instructions. Invalid files and missing optional directories do not stop the session; diagnostics identify the ignored path and reason. Workspace scans exclude `.git`, `bin`, `obj`, `node_modules`, and `packages`. A source never follows a directory link outside its configured root or into a cycle. Duplicate skill names compare case-insensitively: relative workspace sources take precedence in profile order, then Claude skills, then absolute sources in profile order.

Session state shows the number of loaded skills and their names, descriptions, source paths, and whether each came from Claude, a workspace file, or an installed file. It also provides diagnostics for discovered, ignored, and duplicate skills without exposing skill contents.

## Durable Architecture And Constraints

The runtime uses Microsoft Agent Framework's native Harness skills provider mechanisms. Claude-compatible directories use the framework-supported file source. Individually matched Markdown files are adapted to the framework skill model and are not appended in full to the system prompt. Skills do not provide executable script runners, shell commands, URL loading, automatic reload, or an OllamaChat-specific skills directory.

The shared session workspace remains the single root for File Access, sandbox execution, relative skill sources, and Claude-compatible skills. Profile persistence contains serializable configuration only; runtime skill sources and loaded skill contents are session-lifetime objects.

## Non-Goals

This capability does not execute scripts or arbitrary files from skills, watch filesystem changes, change a running session's workspace, transfer history across workspaces, load skills from URLs, or provide a separate `.ollamachat` skills directory.

## Acceptance Criteria

- Users can manage Skills Provider profiles with named Claude-skill inclusion and ordered multi-pattern file sources.
- A saved agent retains its optional selected Skills Provider profile across creation, editing, copying, loading, and execution mapping.
- Relative sources use the fixed session workspace, while absolute sources work without being required to exist when the profile is saved.
- Skills are discovered once at session creation, use the required precedence and case-insensitive duplicate resolution, and leave the provider disabled when no valid skill is found.
- Invalid files, missing optional directories, excluded directories, and duplicate skills do not stop a session and yield useful diagnostics.
- The Harness receives the effective native skills source; skill content is not manually injected into agent instructions and no script runner is registered.
- Active session state identifies loaded skills without displaying their full contents.
- A conversation that has started rejects workspace changes with a clear instruction to start a new conversation.

## Verification

Automated coverage verifies profile persistence, validation, cloning and execution mapping; relative and absolute resolution; Claude directory inclusion; glob matching and exclusions; frontmatter validation; case-insensitive precedence and diagnostics; disabled provider behavior; native Harness options materialization; session-state skill projection; rejection of workspace changes after conversation start; and continued startup when one skill is invalid. Integration coverage verifies a workspace containing both a Claude skill and a glob-matched workspace skill. Manual verification confirms profile management, agent profile selection, the active session skill list, and clear workspace-change guidance after a conversation has begun.
