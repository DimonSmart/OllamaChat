# IDD-0029.spec-development-startup

## Intent

OllamaChat must support both end-user executable startup and predictable backend-only startup for development, debugging, automated testing, and coding-agent workflows.

## Related Specifications

- IDD-0020: C#/.NET and Microsoft Agent Framework architecture.

## Behavior

- Normal non-development application startup may open the default browser after the web host is ready.
- Normal non-development executable startup stops the host after the final active browser session disconnects, allowing a short grace period for reconnects.
- Development startup must not open a browser automatically.
- Development startup must keep the host running when browser sessions disconnect; its lifecycle is controlled by the developer, coding agent, or other host process.
- A dedicated backend development profile must provide a stable loopback HTTP address suitable for browser automation and coding agents.
- The application must expose a lightweight readiness endpoint that returns success when the web host is available and does not depend on Ollama or other external services.
- Browser auto-launch must remain explicitly suppressible for non-development automation such as package smoke tests.

## Durable Architecture And Constraints

Browser launching is an optional host concern and must never be required to access or operate the web application.

Development automation must be able to start, stop, restart, and connect to the application without interacting with a system browser process created by OllamaChat.

Browser-session activity must not control the lifecycle of a development host. Readiness requests must not affect application lifetime in any environment.

The readiness contract must remain cheap, deterministic, and independent of external model-server availability.

## Non-Goals

- Providing a general-purpose process manager.
- Implementing browser automation inside OllamaChat.
- Replacing ASP.NET Core launch profiles or environment configuration.

## Acceptance Criteria

- Development startup leaves browser lifecycle under the control of the developer or coding agent.
- Closing the last browser session stops a normal non-development executable after its reconnect grace period, but never stops a development host.
- Packaged/non-development startup retains the existing end-user browser-opening behavior unless explicitly disabled.
- A canonical backend development profile binds to a known loopback HTTP URL.
- A successful readiness request confirms that the application host can accept HTTP requests.
- Existing headless package smoke tests can continue suppressing browser launch.

## Verification

Verification establishes that development startup does not create a browser process or stop after its last browser session disconnects, non-development executable startup can still request browser launch and stop after its final browser session disconnects, the backend profile binds predictably, and the readiness endpoint succeeds without Ollama being available or affecting application lifetime.
