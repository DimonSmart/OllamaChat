# IDD-0016.spec-built-in-workflow-state

## Intent

Provide application-owned state for a workflow run without duplicating conversation memory.

## Related Specifications

Related: IDD-0001, IDD-0003, IDD-0007, IDD-0028.

## Behavior

Workflow runtime can initialize and expose declared start inputs, normalized source documents, parameters, current phase or status, and named outputs or Markdown summaries. Participants receive only the workflow state required by their configured role. A reduced MCP surface may expose that state when participants require tool-mediated access, but it does not present itself as conversation memory and minimizes generic mutation by models.

Philosopher Battle and Scenario Dispute retain access to their configured launch parameters and documents, their judges retain the ability to publish final output and record completion, and both workflows complete autonomously. Interview Coach obtains conversation history from the HarnessAgent or workflow conversation context; any durable observations needed by later stages are explicit workflow outputs rather than copied transcript turns.

## Durable Architecture And Constraints

Workflow-run identifiers scope inputs, documents, parameters, phase, and named outputs. Normal Markdown launch inputs and source documents continue to be normalized through the application-level Markdown document-intake service before workflow use. HarnessAgent session and Saved Chats infrastructure remain the owners of normal conversation history; workflow state contains no persisted transcript copy.

## Non-Goals

Workflow state does not append, list, or persist conversation turns. It does not infer success or create an unrequested output. Document intake is not independently exposed as an MCP server.

## Acceptance Criteria

- Philosopher Battle and Scenario Dispute can read all configured inputs needed by their participants and complete autonomously.
- Workflow judges can replace their named final output without corrupting other outputs and can record workflow completion.
- Interview Coach uses conversation context without writing a second transcript into workflow state.
- Workflow state exposes no append-turn or list-turn operation and persists no normal conversation history.
- Markdown launch inputs and source documents still reach workflows after application-level normalization.

## Verification

Automated workflow coverage verifies run scoping, document and parameter access, phase transitions, summary replacement, autonomous completion and final judge output for both debate workflows, and absence of duplicate transcript storage in Interview Coach.
