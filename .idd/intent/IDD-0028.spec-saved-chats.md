# IDD-0028.spec-saved-chats

## Intent

Provide locally persistent, resumable saved chats for direct agents and workflows.

## Related Specifications

Related: IDD-0001, IDD-0010, IDD-0023.

## Behavior

Completed stable turns are saved automatically by default. A saved chat has a user-editable title, metadata for listing and search, its complete transcript, launch information, and, for direct saved agents, an optional native runtime session. The first user request supplies a deterministic title of at most 32 Unicode characters; a manually renamed title is retained. Users can search, rename, and open saved chats on a dedicated Chats page. Opening validates the saved format and target before replacing a stable current chat; active, approval-paused, failed, or otherwise unstable chats are not silently replaced. Opening restores the transcript and, when available, native direct-agent state. A workflow resumes using its current resolvable definition and the restored transcript as conversation history.

## Durable Architecture And Constraints

Each chat is an independently written versioned JSON document under the configured local Saved Chats root. Checkpoints replace the complete document atomically and never persist partial streams, pending approvals, session approval grants, diagnostic traces, cancellation state, or UI state. The list reads only summary metadata and tolerates corrupt individual files. A newer unsupported format is rejected without attempting an unknown deserialization. Existing chats remain openable when automatic saving is disabled.

## Non-Goals

Saved chats do not provide deletion, folders, tags, pinning, cloud synchronization, encryption, full-text transcript indexing, autosave timers, or LLM title generation. Manual Harness session export and restore remain separate low-level functionality.

## Acceptance Criteria

- A completed chat persists across navigation, circuit shutdown, and application restart.
- Continuing a saved chat updates its existing document; New Chat does not delete it.
- Search is local and list ordering is most recently updated first.
- Restored messages retain their visible content and metadata, and a direct agent continues its native context when compatible.
- Failed, cancelled, streaming, or approval-paused turns cannot overwrite the last stable checkpoint.
- The Chats page follows the shared compact UI patterns.

## Verification

Automated coverage verifies atomic replacement, resilient summary listing, deterministic title normalization, settings defaults and backward-compatible loading, stable-turn checkpoint rules, transcript restoration through chat events, direct-agent resume compatibility, and workflow history after reopen. Manual coverage verifies search, rename, open errors, navigation placement, and reopening after restart.
