# IDD-0034 — Local Codex Markdown plugins

## User intent

OllamaChat connects a Codex-compatible Markdown plugin from an existing local
directory, without altering the plugin or installing marketplace packages.
The first interoperability case is generated idd-intent, but no application
behavior is hardcoded to IDD.

## Required behavior

- Plugins screen: register local folder, list name/version/description/Skills,
  enable or disable it, remove registration without deleting files; persist.
- Read .codex-plugin/plugin.json for name, version, description and relative
  skills path. Ignore unknown fields and idd-plugin.json. Reject escape paths.
- Skills Provider Profile selects plugin IDs alongside existing Claude, workspace
  and installed sources. Existing profiles without plugins are still valid.
- Saved Agents and CLI both use the profile and the Microsoft Agent Framework
  file-backed Skills sources; merge enabled selected plugin Skills with direct
  sources.
- Keep passive references/ on demand rather than embedding all Markdown in
  system instructions; preserve progressive disclosure.
- Active sessions retain cached Skills; changes take effect in new sessions.
  Diagnostics associate Skills with the originating plugin.
- Missing registration or directory, invalid manifest/Skill and duplicate names
  cannot prevent valid other Skills from working. Conflicts follow first-wins
  semantics and produce diagnostics.

## Boundaries

Local Markdown Skills and passive resources only. No marketplace, hooks,
scripts, IDD workflow router, custom skill-loading tools, subagent delegation,
or changed file, tool, and workspace permissions.

## Verification

Automated tests cover persistence, enable/disable/remove, path validation,
duplicate resolution and native Skills reference discovery. A separate
real-local-LLM smoke verifies Skill and reference tool calls in the Harness
trace; no mock LLM substitutes for this test.
