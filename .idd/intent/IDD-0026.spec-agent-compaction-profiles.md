# IDD-0026.spec-agent-compaction-profiles

## Intent

Let users configure reusable, named context-compaction policies for saved Harness agents.

## Related Specifications

Related: IDD-0001, IDD-0005, IDD-0006, IDD-0009, IDD-0020, IDD-0023.

## Behavior

Users can create, edit, search, and delete reusable compaction profiles. A saved
agent optionally selects one profile; no selection means compaction is disabled.
Profiles offer a recommended context-window policy and an ordered custom pipeline
of supported strategies. The order of a custom pipeline is significant and is
retained when the profile is saved.

Profiles resolve their context and output budget either from the model selected
for the agent session or from an explicit fixed budget. Users can maintain
runtime context and maximum-output limits for a server model without changing
the agent template. A selected-model profile cannot start when its limits are
unavailable or invalid; the user receives a clear correction path before an LLM
request is sent.

Compaction affects only the runtime context held by the Harness agent. The full
user-facing transcript remains available and is neither removed, summarized, nor
rebuilt from compacted runtime history. A session identifies the applied profile,
input budget, and concise policy summary.

Summarization may use the primary agent model or a separately selected model.
The product warns that a generated summary becomes trusted context and therefore
requires a trusted model and endpoint.

## Durable Architecture And Constraints

Compaction profile persistence contains only serializable configuration values;
it does not retain framework runtime strategy objects, chat clients, delegates,
or other runtime instances. Runtime materializes valid profile definitions using
the established Microsoft Agent Framework Harness facilities, which remains the
owner of session history and compaction.

Invalid profile, budget, or stage configuration is rejected before an agent
invocation and must not silently disable a selected profile. Runtime model limits
are stored independently of each agent template and remain available when a
model is temporarily undiscoverable.

## Non-Goals

This area does not define a separate compaction engine, compacted-transcript
storage, synchronization of runtime history with the UI transcript, custom tool
formatters, arbitrary code delegates, or a live timeline of compaction events.

## Acceptance Criteria

- A saved agent can select a reusable profile or explicitly have no profile.
- Existing agents without a profile preserve their non-compacting behavior.
- Context-window profiles compact old tool results before truncating old history.
- A custom pipeline preserves and applies the configured strategy order.
- Summary configuration supports the primary model and a separately selected model.
- Runtime validates required model limits and profile settings before the first LLM call.
- The complete UI transcript remains visible after runtime compaction.
- A profile in use by a saved agent cannot be deleted.

## Verification

Automated coverage verifies profile persistence and validation, model-limit
resolution, runtime strategy materialization, template mapping, and rejection of
invalid selected profiles before invocation. Integration coverage verifies that
the Harness receives the resolved policy while an unselected profile leaves
compaction disabled. Manual verification confirms compact profile editors,
model-limit editing, profile selection on saved agents, retained custom-stage
order after restart, useful launch errors for missing limits, session policy
display, and retention of the complete UI transcript.
